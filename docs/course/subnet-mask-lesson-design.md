# 子网掩码入门 · Lesson 设计稿

状态：Pilot 开发候选；3～5 分钟为试学目标，尚未测量。

## 基本信息与核心问题

- Lesson ID：`subnet-mask`；标题：子网掩码怎样划分地址？
- 所属章节：基础 · 认识地址，紧接 `ipv4-address`，不改变原五课 ID。
- 主要 KnowledgePoint：`ipv4.mask-prefix-equivalence`。本课顺带提供 `ipv4.prefix-length` / `ipv4.network-host-parts` 的最小解释，使现有仅学过四段地址的用户能进入；不是宣称完整 Draft 先修课已经发布。
- 核心问题：同样的 32 位地址，怎样知道哪里是网络部分、哪里是主机部分？
- 可观察目标：根据给定连续掩码 / 前缀选出分界；解释掩码的 1 与 0；在地址值改变但掩码不变时判断分界不变。

## 先修、情境与初始预测

先修只要求 `ipv4-address` 中的四段、每段 8 位、0 / 1 与全 1 等于 255。不能默认懂二进制换算、CIDR、网络地址计算或地址类别。

场景为阅读一张 IPv4 配置卡，并非执行真实网络配置。初始给 `10.20.30.40`，不给掩码，问能否只凭四段数字确定网络 / 主机分界。错误项代表“默认前三段永远是网络部分”；预测错也可进入讲解。

网络部分用来标识给定配置下的子网，主机部分区分其中的接口；不用“前三段永远相同”“掩码是另一台设备的地址”或“主机位越多必然可以通信”的简化。

## Teaching Interaction Kit 与 semantic stages

主要模板 `focus-annotation`，辅助 `decompose-compose` / `condition-toggle`。三者在同一地址场景中组合：看局部 → 显示八位掩码 → 改变唯一条件。状态为首次真实 Pilot，尚不升级 Reusable / Stable。

采用原生 SwiftUI：四行地址字节与掩码对应，点行聚焦后拆开该掩码字节。现有 IPv4 Web 图示保持原样；不创建通用注册表或按 Lesson ID 分支。

| Stage | 画面 / 焦点 | 用户动作与结果 | 回看 |
| --- | --- | --- | --- |
| 0 | 四段地址，暂无角色划分 | 读到为什么还需要分界规则；选择看看掩码 | 是 |
| 1 | 同一地址，加连续掩码与 `/24` | 分别点网络字节和主机字节；局部掩码拆成 8 位，1 标记网络位、0 标记主机位 | 是 |
| 2 | 同一地址与当前分界 | 切 `/24` ↔ `/16`；地址值保持，网络 / 主机位数和角色改变 | 是 |
| 3 | 同一地址，给 `/8`，暂不显示答案分区 | 点选第几段之后，提交后 Core 判断；错可改选，正确后稳定显示分区 | 是 |

练习前不显示掩码位图、网络 / 主机标签或颜色分区，以免提前泄露分界。提交后的提示按前缀从左数位；错误不播放网络故障隐喻。

## 操作练习与迁移判断

观察要求亲自点过网络与主机各一段，并至少切过一次条件；不以观看动画计为掌握。随后两项轻量连线确认 1 / 0 的作用。

最后场景保留 `/16`，只把地址换成 `192.168.8.25`，问分界位置是否变化。正确：仍在第 2 段后；误区：看到 192 自动采用前三段 /24；另一误区：掩码相同意味着两个地址完全相同。本题检验不变量，不拿已展示的同一个场景再当 Challenge。

## 无障碍、布局与边界

使用可缩放系统文字、纵向字节行和原生按钮；二进制 8 格在窄屏 / 大字号下换行。每行的 VoiceOver 标签说明地址段、掩码、角色和可操作用途。静态结果与文字表达同样因果；Reduce Motion 关闭角色变化动画，按钮不依赖手势。无 Web 加载依赖，无需新增 Web fallback。

本课限定连续掩码及字节边界 `/8`、`/16`、`/24`，但明确边界也可落在段中间；不教 A/B/C 分类、网络地址按位与、广播地址、可用主机数、`/31` / `/32`、网关、路由或通信保证。一般前缀计算可验证 `/0…/32`，不将数学支持宣称为教学覆盖。

## 来源

### Pedagogical references

- Kurose / Ross，Top-Down 第 8 版 §4.3.2，纸书 pp.334–337（PDF pp.362–365）：定向查阅地址 / 子网与显式前缀的衔接；用于检查先说明分界再讲交付的认知顺序，不采用其原例题、图示或分类讲法。
- 户根勤《网络是怎样连接的》第 2 版：已视觉检查“本书的结构”纸书 p.12（PDF p.13）的因果叙事；本轮掩码目标页尚未定位核实，不把该书列为掩码断言的依据。

### Technical sources

- [RFC 4632 §3.1](https://www.rfc-editor.org/rfc/rfc4632#section-3.1)：32 位地址、显式前缀长度及连续高位 1 / 低位 0，支持 `/16` / `/24` 与掩码对应。它是本课主要技术依据。
- [RFC 950 §2.2](https://www.rfc-editor.org/rfc/rfc950#section-2.2)：地址之外的掩码配置及位选择语义；仅作历史机制参考。该 RFC 含旧类别与非连续掩码内容，不把其全部规则用于现代入门课。

### WangGan adaptation

用自创配置卡围绕一个边界判断形成闭环；同一场景保留地址值，变掩码后再检验地址值变化的不变量。先用字节边界降低负担，明确不把此范围当普遍限制。
